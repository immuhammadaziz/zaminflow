# Backend requests discovered during frontend Step 0

These are gaps in the current API/contract, not frontend assumptions. No endpoint or field should be simulated in the client. The user must decide priorities and the backend owner must implement/approve any additions.

| Priority                               | Request                                                                                                                                                                                              | Why the frontend needs it                                                                     | Current limitation                                                                                                                                                    |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Required before definition-of-done E2E | Add a development-only deterministic seed command and document demo accounts/roles/passwords/statuses, including a verified approved farmer, processor, and MFA-enabled admin; never seed production | Required clean-stack journey and real dashboard data                                          | No seed command or seeded demo credentials exist; README mentions CLI admin provisioning only                                                                         |
| High                                   | Replace generic dashboard KPI/chart/table schemas in `openapi.yaml` with precise role-specific response schemas                                                                                      | Required generated, strict API types and CI drift checking                                    | `Dashboard` uses `additionalProperties: true`; TypeScript generation cannot type dashboard payloads precisely                                                         |
| High                                   | Add read access to quality-report history per order and/or party                                                                                                                                     | Farmer quality reports and processor quality acceptance/history screens                       | Only `POST /orders/{orderId}/quality-reports` exists; `Order` exposes `qualityOutcome`, not report measurements/history                                               |
| High                                   | Add organization/farm resource support or confirm one organization per user is the full product model                                                                                                | Farmer “farms” screen and edits                                                               | Current profile has one `organizationName`; no farm CRUD/list routes                                                                                                  |
| High                                   | Add a processor-safe supplier profile/directory route with only approved, intentionally public fields                                                                                                | Supplier list/detail and meaningful supplier information on listing cards                     | Listings expose `farmerId`, region and offer values, not seller name/organization/verified profile; no supplier route                                                 |
| Medium                                 | Add supported listing filters for fat-percent bounds and price bounds / max volume if those are product requirements                                                                                 | Requested marketplace filtering                                                               | `GET /listings` supports `regionCode`, `minLiters`, and sort (`newest`, `oldest`, `price_asc`, `price_desc`) only                                                     |
| Medium                                 | Add an admin user-directory list/search/filter endpoint                                                                                                                                              | User directory, suspend/reinstate discovery                                                   | Admin can list pending verified applications and mutate a known user ID; no general user directory/search                                                             |
| Medium                                 | Emit `Retry-After` on `429 rate_limited` responses, with documented units/value                                                                                                                      | Required reliable retry countdown UX                                                          | The rate-limit path currently returns only the shared error envelope; no `Retry-After` header is set                                                                  |
| Medium                                 | Add exact localized display labels or maintain a documented label-key catalog for statuses/regions/errors                                                                                            | Prevent generated clients from relying on ad-hoc translations                                 | Region labels are multilingual; status/error values are stable codes but no complete localization catalog exists                                                      |
| Medium                                 | Document and type the JSON `recoveryCodes` response for `POST /auth/totp/recovery-codes/rotate`                                                                                                      | Allow an administrator to safely rotate recovery codes and display the new codes exactly once | The endpoint description says new codes are shown once, but its OpenAPI 200 response has no content schema; the frontend must not call it or imply rotation succeeded |
| Documentation                          | Add `docs/DATA_MODEL.md` and describe migrations, row ownership, state transitions and operationally seeded data                                                                                     | Prompt's mandatory ordered Step 0 review and onboarding                                       | Requested document is absent; schema evidence currently lives in migrations and implementation docs                                                                   |

Until approved and implemented, frontend design must visibly mark unsupported surfaces as deferred rather than show empty fake pages or invent routes.
